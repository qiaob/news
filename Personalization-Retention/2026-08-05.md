# 推荐与留存日报 — 2026-08-05

## 今日头条：Netflix 发布 GenPage——用单个 Transformer 端到端「生成」整张首页，替代多级推荐栈

Netflix 在近期论文/工程博客 GenPage 中提出一种端到端生成式首页构建方法：把用户与请求上下文当作「prompt」，用单个 Transformer 自回归地把整张多行首页（行、条目、版式）一起生成，而不像 TIGER、HSTU、OneRec 等只生成扁平的排序列表。训练上采用「先在生产页面上预训练、再用加权二分类（WBC）或强化学习（RL）后训练」的 LLM 式配方，并针对冷启动、模型新鲜度、业务规则约束、服务效率给出工程化方案。线上 A/B 显示核心互动指标 +0.24%、服务时延降低约 20%。

「为什么重要」：交友产品的「发现页/推荐流」本质也是「行 + 条目 + 版式」的组合排布。GenPage 证明「用一个生成模型同时决定给你看谁、以什么模块和顺序呈现」在工业规模可行且能降时延——这为 CMB 把「召回→排序→重排→版式」的多级栈收敛为统一生成式体验提供了可借鉴的范式，也提示要同步解决冷启动与业务规则（如互惠、公平曝光）的硬约束。

**Meta 发布 Mosaic：用「一支用户 Embedding 专家舰队」做推荐，被 RecSys '26 收录**

Meta 的 Mosaic 提出用一个异构的「专家 embedding 模型库」取代单一主干（single-backbone）的用户建模范式：不同专家模型各自擅长不同信号，并配以在线 + 离线、CPU/GPU 混合的服务栈，让每个专家按新鲜度、时延、算力需求选择合适的服务策略。论文称在离线与线上均取得稳定且显著的收益。

「为什么重要」：交友场景的用户信号高度多样（长期偏好、近期活跃、双边互惠、安全信号……），单一 embedding 往往顾此失彼。「专家舰队」思路允许把「实时行为」与「稳定画像」分而治之，再按时延预算灵活组合——对既要实时性又要控成本的匹配系统很有参考价值。

[原文链接](https://arxiv.org/html/2607.24015v1)

**值得一读：LLM × 推荐系统的综述，梳理生成式推荐如何补齐传统推荐的短板**

一篇较新的综述《A Comprehensive Review on Harnessing Large Language Models to Overcome Recommender System Challenges》系统梳理了 LLM 用于推荐的思路：作为特征/知识增强、生成个性化解释、合成训练数据、乃至直接作为「理解自然语言 query 的推荐器」，用以缓解冷启动、长尾、可解释性等传统推荐痛点。可作为团队对齐「生成式推荐路线图」的入门读物。

「为什么重要」：CMB 要落地「对话式发现」「AI 破冰」「可解释匹配理由」等功能，需要先厘清 LLM 在推荐链路里的合理落点（增强 vs. 替代）。这类综述能帮助避免把 LLM 当银弹，聚焦真正能提升匹配质量与留存的环节。

[原文链接](https://arxiv.org/pdf/2507.21117)
