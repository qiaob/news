# 推荐与留存日报 — 2026-08-06

## 今日头条：值得从业者精读——用「反事实」纠偏互惠推荐里的曝光反馈环

交友、招聘、游戏组队这类需要「双向接受」才算成功的场景，核心难题是：历史日志由过去的曝光策略生成，热门 profile 被反复展示、长尾被系统性埋没，模型据此学习会自我强化这条反馈环。论文《Counterfactual Reciprocal Recommender Systems for User-to-User Matching》(arXiv:2508.01867) 正面处理这一点：把「谁被展示过」当作可纠偏的干预，用反事实/倾向性加权来估计「若换一种曝光会怎样」，从而在训练互惠匹配模型时抵消曝光带来的流行度偏置。对 CMB 这类双边匹配产品，这是一篇讲清「为什么单看点击/回复日志会越推越窄」的机理文章。

「为什么重要」：互惠推荐是交友产品的算法命门。理解并落地「曝光反事实纠偏」，能直接缓解「热门吃掉所有曝光、新用户与长尾无人问津」的公平性与留存问题——这既是留存曲线，也是供给侧生态健康度的问题。

**框架视角：LLM 之后，推荐系统的四条演进路径**

一篇被业界广泛转发的分析把「后 LLM 时代」的推荐系统归纳为四种范式：(1) LLM 直接充当推荐器（生成式/排序）；(2) LLM 作为组件增强经典召回-排序管线；(3) 对话式推荐，用自然语言完成发现与解释；(4) 智能体式推荐（多 agent 协作、带记忆与工具）。它提示团队不要把「上 LLM」当成一个二元开关，而应按场景选择「用在哪一层、承担多大权重」。

「为什么重要」：交友产品的发现体验正从「刷卡片」向「对话式找人 + 可解释匹配」迁移。这套四范式给 CMB 一个清晰的决策框架：哪些环节用 LLM 做重排/解释即可、哪些值得投入做对话式或 agentic 发现，避免为了「生成式」而推倒可用的经典管线。

**生成式/智能体推荐持续升温：多模态记忆 + 互惠排序融合成为新组合拳**

持续更新的生成式推荐论文清单显示，近期一批工作把「智能体 + 长期记忆 + 融合排序」串起来：例如 MMEACR 用双轨记忆架构，让协作式的 User/Item 记忆 agent 各自推理，再通过加权的 Reciprocal Rank Fusion 融合结果。趋势是把「检索-排序-重排」的静态管线，改造成带记忆、可反思、多路召回再融合的动态系统。

「为什么重要」：对交友场景，「带记忆的 agent + 互惠排序融合」几乎是为双边匹配量身定制——既能记住用户长期偏好演化，又能同时兼顾「我喜欢谁/谁会喜欢我」两侧信号。CMB 可先在小流量上试点「记忆 + 融合重排」，验证对回复率与长期留存的增益。
