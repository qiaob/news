# 推荐与留存日报 — 2026-08-09

## 今日头条：Netflix 发布 GenRec——把用户历史「说成自然语言」，走向 LLM 原生推荐

Netflix 技术博客介绍了 GenRec：不再靠人工特征工程，而是把丰富的用户历史与上下文「语言化」，将原始交互信号直接编码进 LLM 的语义空间，让模型自己去发现物品关系、用户兴趣演变等更高层的模式。这是把推荐系统从「特征 + 排序模型」范式，向「LLM 原生、以语言为中介」范式迁移的一次系统性实践。

「为什么重要」：交友场景的双边互惠推荐（reciprocal recommendation）同样苦于「行为信号稀疏、意图难以特征化」。GenRec 的「语言化用户历史 + 让 LLM 发现模式」思路，为把「谁适合谁、为什么」编码进语义空间提供了可借鉴的工程路径——尤其适合冷启动与长尾用户。

**Pinterest：把 16000+ 条「终身用户行为」喂进推荐，显著提升个性化**

Pinterest 工程团队分享了如何用超过 1.6 万条「终身用户行为」序列来增强推荐：显式建模每条行为的时间戳、行为类型、发生的界面（surface），并为内容引入 32 维 PinSage embedding，基于 embedding 空间的点积相似度做最近邻选择。核心思路是「用足够长的行为历史 + 结构化行为特征」逼近对用户长期兴趣的刻画。

「为什么重要」：交友产品里，用户的滑动、聊天、举报等长期行为同样是留存与匹配质量的金矿。Pinterest 的做法提示：与其只用近期行为，不如把「终身行为序列 + 行为的上下文（在哪个界面、什么类型）」结构化建模，对识别真实偏好和降低误匹配都有直接价值。

**Pinterest：请求级去重让排序吞吐提升 7 倍，得以上线大 100 倍的模型**

另一篇 Pinterest 工程博客介绍了「请求级去重」（request-level deduplication）：在一次请求内消除重复计算，使排序服务吞吐量提升 7 倍，从而能在不成比例增加服务成本的前提下，部署规模大 100 倍的排序模型。这是一条「靠工程优化换模型容量」的典型路径。

「为什么重要」：想上更大的排序/重排模型，往往卡在推理成本而非算法。对预算有限的交友产品，「先做请求级/特征级去重等服务侧优化，再换大模型」是更务实的顺序——把省下来的算力预算花在真正提升匹配质量的模型容量上。
