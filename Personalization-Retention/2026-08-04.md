# 推荐与留存日报 — 2026-08-04

## 今日头条：深读「互惠推荐系统再审视」——为什么 dating 的双边匹配要换一套指标

论文《Revisiting Reciprocal Recommender Systems: Metrics, Formulation, and Method》（arXiv:2408.09748）系统性反思了互惠推荐（reciprocal recommendation，RRS）这一 dating/招聘等双边场景的核心问题：与传统单边推荐只优化「用户喜欢物品」不同，RRS 要同时满足 A 对 B、B 对 A 的双向意愿，一次成功的匹配需要「双向都点头」。作者指出既有工作在评估指标与问题形式化上存在偏差——常用指标未能真正反映「互惠命中」，并据此提出更贴合双边目标的度量、形式化框架与方法。对交友产品，这直接关系到「推给谁、如何排序、如何统计成功」的底层定义。

「为什么重要」：CMB 的推荐本质就是互惠匹配。若线上指标仍以单边 CTR/右滑率为主，容易优化出「一方狂喜、另一方不回」的虚假活跃，抬高曝光却压低真实配对与留存。把评估切换到双向意愿与互惠命中，能让召回、排序、重排更对齐「promising connection」这一真正北极星，也更能解释为何某些高点击策略并不带来更多成功对话。

[原文链接](https://arxiv.org/abs/2408.09748)

**LLM × 推荐工程：如何把数值与稠密 embedding 特征「喂」进 LLM 推荐器**

新论文《Tokenizing Numerical and Embedding Features for LLM RecSys》（arXiv:2607.10016，7 月上线）聚焦一个落地痛点：把 LLM 用作推荐器时，价格、时长、活跃度这类连续数值特征，以及来自双塔/图模型的稠密 embedding，很难自然地表示成 token 塞进语言模型。论文探讨对数值与 embedding 特征做「tokenize」的方案，让 LLM 推荐管线既能吃文本语义、又不丢弃工业界积累多年的数值与向量特征，弥合「生成式推荐」与「传统特征工程」之间的鸿沟。

「为什么重要」：交友产品的关键信号大量是数值与向量——距离、活跃时段、历史互惠率、人脸/兴趣 embedding。若要用 LLM 做对话式发现或生成式重排，能否无损地把这些特征接进去，直接决定效果与成本。这类方法为「在不推翻现有召回/排序特征体系的前提下引入 LLM」提供了工程路径，比「纯 prompt 丢档案」更可用。

[原文链接](https://arxiv.org/abs/2607.10016)

**温故：Eugene Yan 谈「LLM 时代如何改进搜索与推荐」**

Eugene Yan 的长文《Improving Recommendation Systems & Search in the Age of LLMs》梳理了业界把 LLM 引入搜索与推荐的主流范式：用 LLM 做特征增强与语义理解、生成式检索、以及作为排序/重排的辅助，并强调多数生产系统仍是「LLM 增强传统管线」而非推倒重来。文章对「何时该用 LLM、何时传统召回排序更划算」给出了务实判断，适合作为团队讨论生成式推荐路线时的共识基线。

「为什么重要」：在预算与延迟约束下，交友产品更需要分清「哪些环节值得上 LLM、哪些环节传统模型足够」。这篇综述有助于团队避免为「对话式发现」的噱头付出不成比例的推理成本，把 LLM 用在语义理解与冷启动等真正有增量的环节，而非全链路替换。

[原文链接](https://eugeneyan.com/writing/recsys-llm/)
