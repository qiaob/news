# 移动平台与应用商店日报 — 2026-08-11

## 今日头条：Google 侧载新规逐步生效，「匿名 App」时代终结——开发者身份验证成硬门槛

作为 Epic 案和解后的落地动作，Google 的 Android 开发者身份验证新规进入执行期：自 2026 年 9 月起，先在巴西、印尼、新加坡、泰国四国，用户将无法安装「未通过 Google 开发者身份验证」的 App（无论来自哪个商店或直接下载 APK）。要在 Play 之外分发，开发者须在 Android Developer Console 完成身份验证、提交企业标识（如 D-U-N-S 号）并登记 App 包名。Google 同时推出「Registered App Stores」计划，让符合安全与质量要求的第三方商店获得更顺畅的侧载安装体验。

「为什么重要」：Android 的「开放」正在被重新定义为「开放但可追责」。对交友应用是双刃剑——一方面第三方商店与自有分发渠道更可行、可绕开部分佣金；另一方面身份验证抬高了灰产、马甲 App 与仿冒交友应用的门槛，长期利好平台生态的信任度与反诈治理。计划出海新兴市场的团队需尽早完成开发者验证，避免 9 月后在这些国家「装不上」。

**年龄信号 API 全面铺开：Apple「Declared Age Range」与 Google「Play Age Signals」进入实操**

为应对美国多州陆续生效的「App Store 问责法」，两大商店的年龄验证 API 已从政策走向落地：Apple 自 6 月 4 日起对得州新账户启用年龄保证、发布 Declared Age Range 与 Significant Change API；Google 对 5 月 28 日后创建的得州账户返回年龄信号、Play Age Signals API 已进入 beta。开发者需读取商店返回的年龄区间并据此「门控内容、关闭购买、管理家长同意」。犹他、路易斯安那等州，以及巴西、印尼、马来西亚、欧盟、英国、澳大利亚的规则紧随其后。

「为什么重要」：年龄合规正从「各家自建验证」变成「读商店 API + 履行义务」的标准动作。对交友应用（天然 18+）意义重大：接入商店年龄信号既能更稳地拦截未成年人注册、降低法律与品牌风险，也把「验证成年」的重活部分外包给平台；但各州/各国口径不一，团队需要一套按地域动态门控的合规中台。

**欧盟 DMA 持续加码：Google 被罚 8.9 亿欧元，Apple 网关地位上诉被驳**

欧盟对两大平台的 DMA 施压未停：欧盟委员会 7 月对 Google 处以 8.9 亿欧元罚款（搜索自我优待 4.6 亿 + 应用商店引导限制 4.3 亿），要求 60 天内整改，否则面临每日最高「全球营业额 5%」的定期罚金；同月欧盟普通法院驳回 Apple 对其「网关企业（gatekeeper）」认定的上诉，Apple 须继续按 DMA 开放 iOS 与 App Store，包括允许开发者在应用内引导用户到外部渠道完成购买。

「为什么重要」：外链支付与「反引导限制」的松动，长期利好交友应用绕开商店 30% 抽成、把高客单的订阅与增值服务导向自有支付。但欧盟的「初始获取费 + 商店服务费 + 核心技术佣金」等新计费结构复杂，实际能省多少需精算；跨区域运营的团队要为「欧盟一套、其他地区一套」的支付与合规双轨做好准备。
